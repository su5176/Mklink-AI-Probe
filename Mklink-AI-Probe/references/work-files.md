# 使用任务的工作目录与清理

仅在 MKLink 使用任务需要生成脚本、日志、采集数据或报告时读取。本页不涉及
MKLink 源码维护、构建安装包或发布。

## 固定一个位置

沿用本任务已确定的绝对路径；首次使用按用户指定位置或目标项目的 `.mklink/`
选择，并告知用户。Windows 路径不得默认落在 C 盘/系统盘，且要确认实际目标
不经目录链接指向系统盘；没有合适位置时先询问，不自动创建另一套临时目录。
不要在 Skill 安装目录、AI 客户端目录、桌面或用户目录根下生成辅助文件。

| 相对工作根目录 | 用途 | 保留方式 |
|---|---|---|
| `work/<任务标识>/` | 一次性脚本、中间转换、工具临时文件 | 任务结束后清理本次可再生文件 |
| `logs/` | 命令输出、串口/RTT/SystemView 原始采集 | 按任务区分文件名，保留诊断所需证据 |
| `reports/` | 摘要、图表、HTML/CSV 等交付结果 | 保留并告知路径 |
| `cache/` | 可复用下载与解析缓存 | 复用，不随每次任务删除或重复复制 |

按需创建子目录，不预先堆放空模板或多份同用途脚本。复用现有命令/API，只有
确实需要组合操作时才写辅助脚本。用户要求保存到其他位置的最终报告、快速启动
HTML、目标固件与工程配置是正式输出，不强行移入临时区。

## 把实际输出指向该位置

- 执行前将示例中的相对输出路径换成工作根目录下的绝对路径；使用当前工具真实
  支持的 `--log`、`--output`、`--out` 或 API 参数，不虚构通用重定向开关。
- 串口 `open/monitor --log` 放入 `logs/`；`serial log --output` 的原始采集也放
  `logs/`；`systemview-report --out` 放 `reports/`。子目录要先创建。
- 需要临时目录的子进程，仅为该进程设置 `TEMP/TMP/TMPDIR` 到本次 `work/` 下；
  需要 Python 辅助脚本时可用 `python -B` 避免散落字节码。不改系统级环境变量，
  也不重启或篡改已运行的 MCP/桌面服务来迁移路径。
- 新启动的 CLI/MCP 需要更新检查或解析 AXF/DWARF 时，可为该进程设置
  `MKLINK_CACHE_DIR` 到工作根的 `cache/`；这是用户指定位置的显式覆盖。未设置时，传入
  `--project-root`/`project_root` 会把解析缓存放入项目 `.mklink/cache/`，不会再默认
  写入用户主目录。已经运行的服务不为迁移缓存而重启。
- 需要在线烧录 Pack 缓存时，可在新服务启动前设置已有的 `MKLINK_PYOCD_HOME`
  到 `cache/pyocd`；先检查已有缓存，迁移需保留内容，不重复下载。
- 当前 SystemView 自动日志固定在真实目标项目的 `.mklink/logs/systemview/`。
  默认工作根目录为该项目 `.mklink/` 时已经集中；如果用户选择了其他根目录，
  必须说明这个限制。不要把 `--project-root` 改成临时目录以假装重定向日志，
  它还决定固件、符号与项目配置的解析。

工具没有输出重定向能力、路径不可写或空间不足时，先说明实际落点与影响，
取得用户对例外路径的同意或暂停该文件生成步骤，不静默回退到 C 盘或其他目录。
本约束不等于修改了应用、更新器、操作系统或 AI 客户端自身的缓存/日志策略。

## 限制增长与收尾

采集前确定时长或空间预算，避免无期限追加；使用工具已有的限时/限额能力。
没有限额能力时明确说明，采用可安全停止的有限采集。不要反复复制完整原始日志，
默认向用户展示摘要和路径。

先停止本次采集并释放文件句柄，再核对要清理的绝对路径、归属及目录链接。
仅清理本次创建且可再生的临时文件；失败日志、唯一原始采集、输入固件、AXF、
项目配置、用户文件及可复用缓存均保留。其他任务或历史日志未经确认不删除。
`.mklink` 可能同时保存连接和工程配置，禁止整体清空；路径不明、链接或文件占用
时报告目录供用户处理，不改权限或强删。结束报告保留文件位置及大文件大小。
