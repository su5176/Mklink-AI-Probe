# 问题反馈

反馈地址：[MicroKeen/Mklink-AI-Probe Issues](https://github.com/MicroKeen/Mklink-AI-Probe/issues)。
只在遇到疑似工具缺陷、用户要求反馈或跟进已报问题时读取本页。

## 提交前

先区分软件异常和接线、供电、目标配置、端口占用、版本不匹配；已有信息足够时不重复要求用户提供。
沿用设备操作边界，不为复现问题追加擦除、加锁、改电压或无限重试。
不能复现也可以提交，但要明确“用户报告，尚未复现”，不要把推测写成根因。

Issue 是公开内容。展示准备提交的正文并取得用户的公开提交授权；仅授权修复本地问题不等于授权上传。
用户已明确开启自动反馈时，在其授权的项目、内容范围和有效期内直接提交，无需每次重复确认；
范围不明确时按单次授权处理。用户撤回后立即停止。反馈授权不授予远端维护权限。

只保留最小必要证据：隐藏用户名、绝对路径、序列号、网络地址、令牌、业务名称及业务数据。
默认不上传 AXF/HEX/BIN、源码工程、完整日志、内存转储、截图或附件；额外公开内容须单独授权。
日志应手工审阅脱敏，不能承诺自动替换已消除所有隐私。安全漏洞或密钥泄露不要提交公开 Issue。

## 报告格式

标题写可观察的问题，例如“SuperWatch 搜索数组名后无法手动折叠”。正文包括：

```markdown
### 使用环境
应用版本/构建号、操作系统、入口（桌面/Web/CLI/MCP/Skill）
探针型号/固件版本、芯片型号；未知写未知，不包含序列号
### 复现步骤
最小步骤、发生频率、是否在当前版本复现
### 预期结果
### 实际结果
### 最小脱敏证据
必要错误文字、已做检查及结果；事实和推测分开
### 公开提交授权
用户已授权公开提交以上脱敏内容；由 AI 整理（或用户自行填写）
```

先搜索相同版本、错误关键字和功能的已有 Issues（包括已关闭的问题）。
相同问题有新证据时，经授权追加到已有 Issue；没有新证据只保存链接，不重复留言。
不要公开访问凭据，也不要要求用户把令牌发给 AI。

有 GitHub 连接器时使用用户身份提交。已有 GitHub CLI 登录时，可以将审阅后的正文保存到
用户工作目录，再执行（路径换成该文件）：

```text
gh issue list --repo MicroKeen/Mklink-AI-Probe --state all --search "错误关键字" --limit 30
gh issue create --repo MicroKeen/Mklink-AI-Probe --title "简短问题标题" --body-file "报告文件.md"
```

正文通过文件或结构化参数传递，不把日志拼接进 shell 命令。没有 GitHub 身份时，保留本地报告并给出
[新建问题入口](https://github.com/MicroKeen/Mklink-AI-Probe/issues/new/choose)，不擅自登录或安装工具。
提交响应不确定时先查询是否已创建，避免盲目重试；同一问题每次会话最多新建一次。

## 跟进

保存 Issue 链接和已提交的版本信息。用户再次遇到相同问题或要求跟进时，读取该 Issue：
PR 已创建不代表已合并，已合并不代表正式版已发布。只有实际发布版本包含修复后才建议更新，
安装仍按用户授权进行。按原步骤重测并经授权反馈结果，不能仅凭 Issue 关闭就宣称问题解决。
维护端自动检查依赖维护者运行环境，不承诺即时回复或自动发布。
