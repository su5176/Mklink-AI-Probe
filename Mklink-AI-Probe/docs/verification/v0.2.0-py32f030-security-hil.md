# v0.2.0 PY32F030K28T6 加锁/解锁真机验证

## 验证对象

- 器件：`PY32F030K28T6`，3.3 V。
- 只读身份：调试 ID 与工厂配置 ID 均为 `0x60001000`，UID 布局标记为 `0x78`。
- 主 Flash：`0x08000000`–`0x08010000`，64 KiB；页大小 128 B，扇区大小 4 KiB。内置 `PY061xx_64.FLM` 的 SHA-256 为 `6635C2EEB8696362533EBCC238346C3AFB127C84F435C3959C9C15A7A0A2BBCE`。
- Option Byte：`0x1FFF0E80`、16 字节；固定 `PY061xx_OB.FLM` 的 SHA-256 为 `DE2460697CC31ABFD897570696BD6ADB901ACD7BBB5401C1DCDAC2F15DC3BCBD`。
- 官方依据：[PY32F030 Reference Manual V1.7](https://download.py32.org/ReferenceManual/en/PY32F030_Reference_Manual_V1.7.pdf) 与 [PY32F030 数据手册 V2.8](https://download.py32.org/Datasheet/zh-CN/PY32F030%E7%B3%BB%E5%88%97%E6%95%B0%E6%8D%AE%E6%89%8B%E5%86%8C_V2.8.pdf)。手册规定 RDP Level 0 为 `AA/55`，其他有效补码值进入 Level 1；从 Level 1 恢复 Level 0 会由硬件整片擦除主 Flash，调试连接期间修改后需要断电复位。

## WebGUI 真机闭环

1. 精确型号 `PY32F030K28T6` 自动解析为内置 `PY32F030x8` 几何。加锁前完整读取 65,536 字节，首向量为 `D8040020D5000008`，SHA-256 为 `39D9382B2C0CB5B5FF89B50C1DD45C86109376BD0B7A62ADED3CBC6FED6B3F02`。
2. WebGUI 在同一任务内先校验完整镜像，再写入可逆 RDP Level 1 `BB/44`，关闭下载器 VCC 1 秒并以 3.3 V 恢复。随后读取主 Flash 得到 SWD `FAULT ACK`，确认保护生效。
3. WebGUI 使用复位下连接写回 RDP Level 0 `AA/55`。器件在 FLM 返回前立即复位并开始硬件擦除；后端只对该芯片、该转换方向及精确 `IPSR=3` 返回特征延后判定，随后执行 3.3 V 断电复位并重新建立 SWD 会话。
4. 新会话重新核对物理 Option Byte、逻辑 `FLASH_OPTR.RDP` 与补码关系，并逐扇区确认全部 65,536 字节均为 `FF`；擦除态 SHA-256 为 `71189F7FB6AED638640078FBA3A35FDA6C39C8962E74DCC75935AAC948DA9063`。
5. 使用同一内置主 Flash 算法恢复完整镜像并校验，断电复位后再次完整回读；最终 SHA-256 与步骤 1 完全一致。最终状态为 RDP Level 0，原程序已恢复。

## 固化边界

- 安全白名单目前只启用精确订货型号 `PY32F030K28T6`；其他 PY32 型号继续置灰，不能通过通用型号绕过。
- 每次安全操作固定校验调试 ID、工厂 ID、UID 布局、64 KiB Flash 几何、Option FLM 名称/哈希/范围以及所有 Option Byte 的补码关系。
- 加锁只写可逆 Level 1 `BB/44`，解锁只写 Level 0 `AA/55`；绝不尝试不可逆保护等级。
- 解锁必须由用户确认永久丢失全部 Flash 数据及恢复电压，并强制复位下连接与 1 秒断电复位。
- CLI、MCP 与 WebGUI 共用同一安全能力白名单和后端实现。
