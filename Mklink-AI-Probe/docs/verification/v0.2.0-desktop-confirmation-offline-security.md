# 桌面安全确认与 V3 脱机保护能力评估

日期：2026-09-03。上位机基线 40a9319；本次修改仅在 MKLink 上位机仓库。
用户提供的 V3/V4 下载器源码只读分析，未修改、编译或升级探针固件。

## 已修复与实测

在线加锁、解锁勾选原先依赖同步 `window.confirm()`，在桌面 WebView 上不能可靠显示。
现在共用页面内风险对话框，不依赖原生 JS 对话框或 Tauri message 权限：

- 勾选时立即显示；明确确认之前复选框保持未选中。
- 取消、Esc、点击遮罩均拒绝；默认焦点为取消，Tab 限制在确认框内。
- 背景工作区 inert；探针、型号、镜像、复位配置变化或离开页面会取消待确认请求。
- 断电复位的逐次电压确认及选择 5V 的警告也使用同一机制。
- 加锁仍自动包含校验和复位；不降低后端白名单及擦除/电压确认要求。

| 验证 | 结果 |
| --- | --- |
| GUI 全量测试 | 60 文件、650 项通过；含取消、Esc、型号变更使确认失效、确认前禁止开始及拒绝电压确认不创建任务 |
| Vue 类型检查、Vite 生产构建 | 通过 |
| Tauri Windows 无安装包构建 | 通过；16.2 MiB 测试 exe，使用源码 Python 开发后端 |
| 实际 Tauri/WebView2 窗口 | 点击解锁/加锁均立即显示风险框，分别取消；没有从该窗口发送硬件任务 |
| 真实 WebGUI | 加锁风险框及取消通过；解锁、3.3V 断电复位确认可操作，不再阻塞宿主 |
| GD32F303CET6 + V3.3.8 真机 | 一条 GUI 作业内依次 connect/unlock/erase/program/verify/reset/disconnect 成功，15.184 秒 |

本轮 GUI 使用之前已获授权的客户合并 HEX，实际数据 180732 B、两个不连续 Flash 区间。
原始文件 SHA-256 为 `64450f723f738c29df9bd2e62b4b83880c0241cdb6d78e92a6e636b0d44fba53`。
恢复电压 3300 mV，复位下连接，解锁永久擦除全片 512 KiB；只恢复 HEX 覆盖的数据。
保护动作由共用在线后端执行，不能把这次结果算作脱机脚本解锁成功。
客户应用会在运行后再次设置读保护；业务外设功能未验证。

测试保留 Node localStorage 实验性警告、一个测试中的 localhost:3000 连接拒绝日志、
Vite 大块提醒及 MSVC linker 提醒；测试/构建退出码为 0。
没有重打 NSIS、覆盖已安装目录、更新 Skill ZIP 或正式发布。已安装旧 exe 不会自动获得修复。

## V3 固件实际能力

只读检查用户提供的 `microlink_app_v3` 及相邻 `external/pikapython`。
真机 `cmd.get_version()` 返回 V3.3.8；四字节 DBG_ID 读取成功，
`type(cmd.read_ram(...))` 返回 `NoneType`，与源码一致。
本次读取的选项字节为 `BB 44 FF FF ...`，与客户应用自锁现象一致。

| 文件/入口 | 发现与影响 |
| --- | --- |
| `external/pikapython/cmd.pyi`、`py_cmd.c:cmd_read_ram` | 读取打印数据，返回 void；可另存文件，但文件打开/写入失败没有完整返回，不能直接充当带状态的选项字节读取接口 |
| `py_cmd.c:cmd_program_page`、`cmd_erase_*` | 已有返回码，可复用 FLM 擦写；不是现成的芯片加锁/解锁事务 |
| `py_load.c:load_flm` | 参数错误后继续取参数；忽略 FLM 解析返回结果，最后返回 0。不能仅凭脚本的 `load.flm(...) == 0` 认定有效 |
| `py_load.c:load_hex_flash/load_bin_flash` | 正常收尾忽略 close 返回值后报告成功；有文件错误路径没有完整关闭 flash 会话 |
| `file_stream.c:close_hex/close_bin` | 关闭时直接调用软件复位，应用可以立即运行并自锁；不适合“所有镜像校验后再统一加锁/复位” |
| `target_family.c:get_flash_blob/target_set_state` | 前者设置 CONNECT_UNDER_RESET，但后者固定调用 `swd_set_target_state_sw`；配置标志不是实际硬件复位下连接的保证 |
| `target_flash.c:target_flash_program_page` | 已有逐页校验：有 Verify 算法则调用，否则 SWD 回读比较。应复用，不应声称脱机完全没有校验 |
| `swd_host.c:RESET_PROGRAM` 等 | 部分等待 S_HALT 循环没有总超时；安全事务需要有界失败和可确定的复位/供电收尾 |
| `target_family.c:software_reset` | 用按位 OR 汇总读写结果；一个成功可能遮蔽另一个失败。应明确逐步检查成功语义 |

V3 Intel HEX 解码器对 03/05 入口记录落入 default 忽略，没有 Python IntelHex 的
“第二条起始地址记录”拒绝逻辑；这不等于整个客户镜像已通过设备端烧录回归。

## 建议怎样配合（待实现，不是现有 API）

可以支持，但不能把在线 pyOCD 白名单成功直接等价为设备端执行器成功。
FLM 负责擦写，安全事务还需要身份检查、选项字节保存/校验、保护状态判断、
真实复位下连接、断电恢复与全过程错误传播。

1. **固件补通用可靠接口。** 提供带成功状态/实际长度的内存读取；明确连接方式；
   正确返回 FLM 解析、擦写、最终 flush/uninit/verify 结果；增加“保持暂停、不自动复位”模式。
   保留旧 `load.hex/bin` 默认行为以兼容现有脚本，新模式才延迟运行。
2. **安全操作使用受限事务。** 首先支持已验证的 GD32F303xE 配方；身份、选项区范围、
   算法哈希必须匹配，检查互补字节并保留非保护选项，拒绝不可逆保护。
   受保护时容量读取可能被拒绝，必须明确处理这一状态，不能把任意总线错误认作读保护。
   解锁后再次读取容量和保护状态，确认擦除完成，失败不得进入编程。
3. **上位机生成完整部署包。** 从 CLI/MCP/WebGUI 共用能力目录导出版本化配方及固定
   OPT/主 FLM 的元数据；绑定镜像范围/摘要、探针所需 API 版本和用户确认电压。
   用户勾选解锁时说明每次执行都会永久擦除；加锁只允许在本次全部镜像校验成功后执行。
   旧固件或没有验证配方的型号置灰，后端同样拒绝，不仅靠 UI 禁用。
4. **设备独立执行。** 正确顺序为：核对设备/文件 → 复位下连接 → 检查/解锁 →
   断电等待 1 秒并按确认电压恢复 → 确认解除保护和容量 → 下载全部镜像并校验 →
   可选加锁 → 最终复位/运行。任一失败停止后续动作，不打印成功。
5. **单板故障回归后开放。** 用当前 GD32 板验证已保护/未保护、连续两轮自锁重烧、
   非默认选项保存、错误芯片、损坏/缺失 FLM、失败校验、断电恢复、USB 断开后独立触发。
   另验证重启后配方/文件完整性；不能仅以脚本“部署成功”或日志出现 finished 验收。

把读取结果落盘再读取、把常量选项字节 BIN 当作普通固件烧写，理论上可拼出板级实验，
但当前缺乏完整错误与暂停/运行控制，不作为可发布的自动解锁方案。未部署任何自动解锁脚本，
未修改现有 U 盘脚本，也未改下载器固件。下一步需用户明确同意固件实现及更新测试。
