# Mac/Linux compatibility and content reload verification

Date: 2026-09-03. Branch: `codex/v0.2.0-development`. Prerelease source validation,
not an installer or release qualification. The physical host was Windows; no
macOS/Linux hardware was available.

## Report assessment and implemented changes

- Project initialization is offline and preserves existing advanced settings.
  Port, FLM and a guessed `mcu_key` are not mandatory initialization inputs.
  Keil namespaces, per-file options and Windows relative separators are handled;
  IAR output discovery also normalizes separators and ignores AppleDouble files.
- Unix volume/serial discovery is platform-aware. Shared paths must be accessible
  from the host running the backend. USB belongs to either the Mac or VM, not both.
  Windows ARM driver compatibility is separate from x86/x64 application emulation.
  See [user guidance and official references](../../references/macos-linux.md).
- Firmware/FLM copies compare SHA-256, flush/sync and verify host readback. Equal
  file length or preserved mtime no longer means unchanged. Host readback is NOT
  proof of MCU Flash verification or an explanation of probe firmware caches.
- Native download success requires explicit completion evidence; an isolated zero
  or missing response is not success. Errors take precedence over progress text.
- AXF/DWARF/symbol identities include SHA-256. Active AXF takes precedence over
  stale project AXF/MAP paths. Missing/unparseable files fail closed; stale symbol
  writes and new SuperWatch starts are refused.
- Backend source monitoring stops dependent streams, reparses symbols and updates
  RTT addresses after content changes. It does not automatically resume capture
  or program a board. The user must first ensure target and symbols correspond.
- RTT View, SuperWatch and the symbol browser refresh dependent state. Online
  HEX/BIN preview/inspection reloads content; source loss disables programming.
  The new “文件路径 / 加载并跟踪” control supports backend-local/shared files.
  Browser plain uploads remain immutable snapshots unless a retained file handle
  grants subsequent access; this browser restriction is documented, not hidden.

The Mac report did not include its failing project, command responses or process
exit logs. Only “MicroKeenV4 latest” was supplied. First-download false success and
backend process exit were NOT reproduced on Mac and are not attributed to a cache.
Register addresses, intentional read-size limits and target M7 cache coherence
are explained in guidance rather than globally disabling safety or target caches.

### Additional issues exposed by HIL

1. Online RAM FLM execution initially failed with `IPSR=3` while attaching to the
   running RTOS; the backend stayed alive and reported failure. Native verified
   programming restored the test application. Custom-FLM destructive operations
   now reset/halt once before the first algorithm execution; read-only attachment
   still does not reset. The same GUI workflow then passed. Exact preceding
   exception/stack/MPU cause was not independently traced.
2. Programming explicitly uses sector erase, preventing pyOCD's cost-based
   automatic escalation to whole-chip erase for an application-only image.
3. A separate trace-lifecycle issue remains: after online programming/disconnect,
   `DEMCR.TRCENA` was zero and repeated DWT cycle-count reads were stationary.
   GUI MCU reset restored TRCENA and advancing cycle counts. Installed pyOCD's
   `CortexM.disconnect()` explicitly clears DEMCR. Preserve/restore semantics
   require a separate tested lifecycle change; no blanket debug-register write
   was added to RTT or SystemView start as a workaround.

## Automated gates and boundaries

Final Python suite: **1767 passed, 12 failed** (all directory-symlink privilege
failures below); GUI suite: **642 passed across 60 files**. GUI production build,
Skill validation and rendered memory validation passed. This is not installer
generation.
Focused coverage includes preserved-mtime/same-size content changes, cache
invalidation, active AXF precedence, disappearing/reappearing files, copy flush
and verification, strict completion parsing, stream stop/rebind, stale writes,
online source loss, and FLM reset/sector-erase policy.

Windows full-suite directory-symlink tests cannot create links under the current
account (`WinError 1314`). Linked scratch directories are retained under ignored
`.build` for safe inspection; they were not force-deleted or converted to skips.
No screenshots, firmware, local hardware paths or device serials are committed.

Modbus/YMODEM peers, remote-host workflows, new security families, Mac/Linux USB
hardware and installers were not available/in scope. Automated coverage does not
substitute for these physical tests. All capture streams are stopped for handoff;
the test application remains programmed and WebGUI remains available.
