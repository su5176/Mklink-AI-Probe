# MKLink AI Probe 0.1.9 STM32F103RE 发布前 HIL

验证日期：2026-08-31

预发布分支：`codex/v0.1.9-development`

验证起点：`34e3b7c141898821cc108182c2443701117a2953`

测试工程：独立的 STM32F103RE RT-Thread HIL 工程（不纳入本仓库）

目标芯片：STM32F103RE

下载器：MKLink V4，固件 `V4.3.9`

## 结论

0.1.9 的 ARM 基线、WebGUI、串口/YMODEM、在线烧录和 AI MCP 安全边界均完成真机闭环，未出现下载器失去响应或需要重新拔插的情况。可以生成 0.1.9 候选发布资产；正式标签、GitHub Release 和主分支合并仍需维护者明确授权。

受控 HardFault 触发后目标自动恢复，宿主仍可连接，但复位已经清除 Fault 状态寄存器。因此本轮只确认 HardFault 命令路径可用，没有把“复位后还原故障现场”记为通过。

## AI Skill 与 MCP 边界

使用真实 stdio MCP 会话串行执行 12 步：`ping`、连接、正常单区读取、正常 16 区连续读取、5 类越界拒绝、拒绝后的再次读取、状态检查和断开。

以下请求均在宿主侧拒绝，拒绝后 4 B RAM 读取、`device_status` 和 CLI `version` 继续通过，下载器没有 quarantine 或死机：

- 单次读 4097 B；
- 17 个批量区域；
- 批量总计 4097 B；
- 单次写 4097 B；
- `flush_memory` 9 个区域。

相关 Skill/MCP/dump-memory 自动化回归为 84 passed。当前安全上限保持为：direct read/write 4096 B，batch 16 项且总计 4096 B，flush 8 项且总计 12288 B，流式 dump 最多 15 个 region；同一只下载器的硬件调用必须串行。
