# SuperWatch 常用类型写入真机验证

## 范围与结果

使用 V4 + STM32F103RE 和原 STM32F103 测试工程，增加不会被任务周期覆盖的
`volatile sw_write` 结构体，保留现有波形、UART 和 RTT 负载。Keil 编译
零错误、零警告，下载后校验成功。AXF 使用内置 DWARF 解析器。

本轮按用户要求使用实际 Google Chrome 与 CLI，不运行原生桌面自动化。
Chrome 通过界面的搜索、编辑、写入按钮操作，逐项核对后端验证结果和目标
RAM 字节；同时比较整个测试结构体，确认相邻字段与首尾哨兵没有改变。

| 类型 | Chrome 实际输入 |
| --- | --- |
| float | `3.1415926`、`-12.5`、`-1.25e-3`、`0` |
| double | `-123.4567890123` |
| int8 / uint8 | `-128`、`127` / `255` |
| int16 / uint16 | `-32768` / `65535` |
| int32 / uint32 | `-2147483648`、`2147483647` / `4294967295` |
| bool | `true`、`false` |
| enum | 名称选择，对应 `-1`、`1`；本机编译结果为 1 字节有符号枚举 |
| 数组元素 | `sw_write.array[1] = -6.25`，其他元素保持原值 |

18 项停止采集时的有效输入通过。`float` 回读遵循 IEEE 754 单精度，例如
`3.1415926` 的实际存储值为 `3.141592502593994`，不是写入错误。
6 项非法输入也已验证：int8 的 `-129`、uint8 的 `-1` / `256`、整数的
`1.5`、float32 的 `1e40` / `-1e40`。拒绝后整个结构体保持不变。

CLI 实际调用 `write-ram` 写入小端编码并回读校验，再用 `watch --json`
按 AXF 类型读取。float、double、8/16/32 位有符号与无符号整数、bool、
数组元素共 10 组通过。CLI `write-ram` 接受字节，不新增按文本类型写入参数。

Chrome 中勾选 float 通道并保持采集，连续 20 次交替写入正、负浮点数，
每次均校验实际 RAM 回读、界面最新值和采集恢复状态。最后写入 `-7.25`，
截图确认曲线变化；没有回读失败或采集读错误。第一次独立复测约 997 Hz，
2488 个完整样本，CRC/帧丢失计数为零，启动文本丢弃 88 字节另行计数。

完整 Python 回归：1901 通过、12 失败。12 项均为原有目录重定向测试在创建
symlink 时遇到 `WinError 1314`，当前进程没有所需权限，尚未执行被测行为；
没有将它们改为跳过或宣称全量通过。本次新增的类型溢出、CLI 类型解析及
迟到停止提示符回归均通过。临时测试目录含链接，按存储规则保留待检查。

## 本轮发现与修复

- 超范围整数原先抛出未处理异常，浏览器只显示 Internal Server Error；现在
  写入接口返回 422 和具体类型/范围错误。float32 有限值溢出也转换成输入
  错误。验证发生在暂停采集与写内存之前。
- 连续采集停止后仅等固定时间，偶尔把迟到的停止提示符作为下一条内存命令
  的完成响应，导致写入回读不一致。现场原始记录包含 `read_ram` 收到
  `dump_memory(..., -1.0)` 尾部响应的证据。现在停止流后确认命令模式并
  验证身份响应，再允许后续命令；同步失败保留错误状态，不盲目重写数据。
- CLI `watch` 原先通过类型名称直接查结构体，不能解析本测试的 typedef
  结构体成员，也不能正确解码部分整数别名。现在标量读取复用 SuperWatch
  的目录和解码逻辑，保留 MAP 回退、Flash 与 HPM 地址读取范围。

## 交付与限制

源码修复同步至本机用户 Skill，WebGUI 后端已重启生效；安装的桌面 sidecar
本轮未重新打包，也未作为本轮测试对象。前端无需修改。

结束时恢复整个写入结构体的初始 RAM 值并回读一致，停止采集、断开设备；
命令口和 UART 均可重新打开后关闭。测试工程保留 `sw_write` 供手动验证。

本轮不是所有 C 类型的穷举：64 位整数、指针、位域写入及其他芯片没有新增
真机证据。采集中修改变量会短暂停流后恢复，不能称为无间隙采集；已有
RTT 启动/停流问题和高速 USB 识别问题不能据此宣布关闭。

原始命令、Chrome 截图、RAM 备份、构建/烧录结果保存在本地忽略目录
`.build/reports/superwatch-write-20260907`；不上传固件、设备标识或用户工程。
