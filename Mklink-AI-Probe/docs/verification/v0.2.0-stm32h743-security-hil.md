# v0.2.0 STM32H743 security HIL

Date: 2026-09-02

## Fixture

- Target marking: STM32H743IIT6
- Resolved built-in target: STM32H743xI
- DBGMCU device ID: `0x450`
- Flash size register: 2048 KiB
- Probe: MKLink V4, target VCC restored at the user-confirmed 3.3 V
- Reference: [STM32H743/753 reference manual RM0433](https://www.st.com/resource/en/reference_manual/rm0433-stm32h743-753-and-stm32h750-value-line-advanced-arm-based-32-bit-mcus-stmicroelectronics.pdf)

## Results

1. Read and saved the complete 2 MiB main Flash before changing protection.
2. Programmed global reversible RDP Level 1 (`0xBB`) while preserving every non-RDP option field.
3. Performed a 3.3 V power-cycle reset. Both option-register aliases reported RDP `0xBB`, and a main Flash read failed with a transfer fault.
4. Connected under reset and programmed Level 0 (`0xAA`). The mandatory main Flash mass erase completed before the 3.3 V power cycle.
5. Both option-register aliases returned to RDP `0xAA`; a 4 KiB Flash sample contained only `0xFF`.
6. Reflashed and verified the complete recovery image.
7. A separate complete 2 MiB WebGUI API readback produced the same SHA-256 as the pre-protection backup.
8. Confirmed the final RDP state remained Level 0 and performed a final 3.3 V power-cycle reset to start the restored firmware.

## Safety boundaries

- Only STM32H743 2 MiB order codes covered by the `STM32H743xI` algorithm are enabled; 1 MiB and ambiguous variants remain disabled.
- Runtime checks require device ID `0x450`, Flash size 2048 KiB, the pinned option-algorithm hash, and its exact metadata.
- Only reversible values `0xAA` and `0xBB` can be written. Irreversible RDP Level 2 (`0xCC`) is always rejected.
- Every non-RDP option field must remain unchanged, or the operation fails closed.
- H743 security jobs require power-cycle reset; unlock additionally requires connect-under-reset.
