# SuperWatch 搜索结果完整性

## 原因与修复

用户启用测试工程的 SuperWatch 压力变量并重新编译后，输入 `superwatch_`
只看到数组，输入 `superwatch_c` 才看到通道。现场只读请求证实：宽泛搜索
接口返回 50 项，全部为 `superwatch_array_wave[0..49]`；更具体的搜索返回
16 个 `superwatch_ch` 通道。当前目录内已有全部 80 个匹配项，AXF 已重载。

界面此前将后端有数量上限的建议结果当作完整搜索结果。修复在共享的
useSymbolCatalog 中同时匹配已加载目录，按路径去重合并后端结果；保留
后端对目录未展开的精确数组下标的解析能力。没有扩大目录生成边界，也不
修改原有数组手动收起、展开和采样逻辑。Web 与 Tauri 使用同一前端代码。
首次实际浏览器测试还发现搜索输入早于目录加载完成的时序问题，因此查询
先等待共享目录加载任务，避免首次进入时仍只使用 50 条后端建议。

## 检查

- 新增回归在旧代码实际失败（预期 80 项，实际只有 50 项）；修复后通过。
- GUI 全量 64 个文件、675 项通过，包含多关键词、大小写匹配、去重、
  未加载的精确数组下标和无匹配结果检查。
- 最终源码 `4ea8127` 的 TypeScript、生产 GUI 和标准 NSIS 构建成功。
- 真实 Edge 使用当前用户 AXF 和实际后端，直接进入 SuperWatch 后立即搜索：
  `superwatch_` 显示全部 64 个数组元素和 16 个通道；收起数组后通道仍显示，
  再展开恢复 64 个元素。窄前缀、大小写、多关键词搜索通过，页面 JS 错误为零。
- 内置浏览器也验证 `superwatch_ch00` 至 `superwatch_ch15` 可见，并停留在
  `superwatch_` 搜索、数组手动收起的状态。
- 本地 Skill 同源运行时同步，配置保留、GUI 与桌面构建逐字节相同，不包含
  维护上下文。sidecar 与 Skill 均验证 7059 目标、2224 FLM 数据文件。
