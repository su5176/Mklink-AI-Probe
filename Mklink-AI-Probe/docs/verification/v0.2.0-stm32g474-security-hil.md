# v0.2.0 STM32G474 security HIL

Date: 2026-09-02

## Fixture

- Target marking: STM32G474RET6
- Resolved Pack target: STM32G474RETx
- DBGMCU device ID: `0x469`
- Flash size register: 512 KiB
- Probe: MKLink V4, target VCC restored at the user-confirmed 3.3 V
- Reference: [STM32G4 reference manual RM0440](https://www.st.com/resource/en/reference_manual/dm00355726-stm32g4-series-reference-manual-stmicroelectronics.pdf)

## Recovery image

- Address range: `0x08000000`–`0x08080000`
- Size: 524288 bytes
- SHA-256: `063A75F1CB15147F8B26A5FCFB406B959EDBA73A2D8B47F5C4E48F60329CEBA4`

## Results

1. Read and saved the complete 512 KiB main Flash before changing protection.
2. Programmed reversible RDP Level 1 (`0xBB`) while preserving every other effective option field.
3. Performed a 3.3 V power-cycle reset. Logical OPTR reported `0xFFEFF8BB`, physical RDP bytes were `BB/44`, and main Flash reads failed.
4. Connected under reset and programmed Level 0 (`0xAA`) through the host-driven equivalent of the pinned G4 option algorithm. The mandatory mass erase completed before the 3.3 V power cycle.
5. Logical OPTR returned to `0xFFEFF8AA`, physical RDP bytes were `AA/55`, all other option fields matched the original values, and main Flash was blank.
6. Reflashed and fully verified the 512 KiB recovery image. A separate complete readback produced the same SHA-256 as the original backup.
7. Repeated the final-code lock, protected-read rejection, unlock, erase, restore, and full verification cycle successfully.
8. Read the restored 512 KiB image through the WebGUI API using the exact alias `STM32G474RET6`; its SHA-256 matched the backup, confirming the exact-to-generic algorithm mapping also applies to readback.

## Safety boundaries

- Only STM32G474 512 KiB order codes covered by the `STM32G474xE` algorithm are enabled.
- Runtime checks require device ID `0x469`, Flash size 512 KiB, the pinned option-algorithm hash, and the exact option-byte region.
- Only reversible values `0xAA` and `0xBB` can be written. RDP Level 2 (`0xCC`) is always rejected.
- G474 security jobs require power-cycle reset; unlock additionally requires connect-under-reset.
- Unsupported or ambiguous devices remain disabled.
