# V4 通用安全执行与 VCC 控制移植

日期：2026-09-05。用户换用 V4 下载器和 STM32F103 测试板，要求移植 V3
已验证代码，由用户完整编译并下载后再进行 HIL。

## 范围

V4 已具备与 V3 相同的通用 FLM/CFG 安全执行器和 Pika 命令绑定，以及取消
HEX/BIN 关闭阶段自动复位的修改。本轮保留这些已有工作，补齐：

- VCC 安全关闭优先于后台 VREF 跟随；显式零输出不被残压重新打开。
- 按 V4 GPIOB 接线释放 SWD 驱动和上拉、释放开漏 RST。
- 安全电源循环临时停止自动跟随，维持 V4 原有电压 API，不照搬 V3 的板级补偿。
- 同步 V3 的复位捕获超时、HALT 等待及完整扇区空白确认回退。

芯片支持仍由上位机生成的配置维护，不向探针固件增加芯片型号表。
上位机默认断电 3 秒、残压门限 800 mV，供电恢复后稳定 1 秒；不改变受支持
器件或保护等级。V4 的 ADC、LCD、PWM 蜂鸣器和 RISC-V 路径保留。

## 升级后 STM32F103 真机回归

同日用户已完整编译、升级 V4，并确认 3.3V、允许可逆保护及解锁擦除。
核对 STM32F103RE、512 KiB Flash 后先双读全片备份，并与 bootloader、APP
AXF 的加载段比对一致。原始镜像、配置、作业日志仅保留在忽略的
`.build/reports/v4-f103-security-20260905`，不上传固件或设备标识。

### 本轮发现并修复的上位机问题

首次在线独立加锁在 option FLM 擦除后发生 HardFault（IPSR=3），诊断同时看到
应用遗留的 PSP/中断上下文。F1 选项算法没有主 Flash 算法已有的执行上下文
准备和中断保护，独立加锁也没有触发上下文复位准备。

- 在擦除选项字节前准备并检查特权 MSP 上下文，异常时拒绝写入。
- 选项字节 FLM 同样在算法调用期间屏蔽中断并恢复原 PRIMASK。
- 完成后使用 `cleanup()`，避免选项与主 Flash 算法共享 RAM 后复用失效代码。
- 保留原有芯片、算法和选项字节校验；不开放 RDP2、不放宽异常选项状态。

首次失败后使用已备份的原选项恢复，断电生效后独立确认全片擦空，再恢复
原始镜像。此后重启源码后端进行以下回归，无需再次修改或升级探针固件。
