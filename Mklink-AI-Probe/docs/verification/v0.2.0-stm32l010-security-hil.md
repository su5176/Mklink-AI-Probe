# v0.2.0 STM32L010 security HIL

Date: 2026-09-02

## Fixture

- Target marking: STM32L010F4P6
- Resolved catalog target: STM32L010x4
- Debug topology provider: pyOCD STM32L031x6 target with L010-specific memory geometry and pinned FLMs
- DBGMCU device ID: `0x457`
- Flash size register: 16 KiB
- Probe: MKLink V4, target VCC restored at the user-confirmed 3.3 V
- References: [STM32L010F4 product page](https://www.st.com/en/microcontrollers-microprocessors/stm32l010f4.html) and [STM32L0x1 reference manual RM0451](https://www.st.com/resource/en/reference_manual/rm0451-stm32l0x1-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)

The main image is a safe minimal Thumb loop used because the connected device was blank. The EEPROM image contains a test marker. Both complete regions were read back before protection and retained for restoration.

## Results

1. The L010-specific custom FLM initially timed out when launched through the generic Cortex-M topology. Using the STM32L031 debug topology and resetting-and-halting exactly once before the first RAM algorithm call made main Flash and data EEPROM erase/program/verify reliable.
2. Programmed and independently read back the complete main Flash and data EEPROM recovery images.
3. CLI `security lock` verified the complete main Flash image immediately before protection, wrote reversible RDP Level 1, and performed a 3.3 V power-cycle reset.
4. The RDP shadow register reported `0xBB`; the physical first option word was exactly `0x014400BB`. Debug reads of main Flash and data EEPROM returned no payload while protected.
5. MCP `security_status` reported exact-model support and all three unlock-erasure effects. MCP `security_unlock`, with explicit voltage and data-loss confirmations, connected under reset, wrote Level 0, and performed a 3.3 V power-cycle reset.
6. The RDP shadow register returned to `0xAA`; the physical first option word was exactly `0x015500AA`.
7. Main Flash, data EEPROM, and backup registers were all zero after the mandatory Level 1-to-Level 0 mass erase.
8. WebGUI services restored and verified both complete recovery images, then performed a 3.3 V power-cycle reset.
9. Separate complete readbacks after restoration produced the same two SHA-256 values as the pre-protection images.

## Safety boundaries

- Only exact STM32L010x4 order codes backed by the pinned L010 algorithms are enabled.
- Runtime checks require device ID `0x457`, a 16 KiB Flash-size register, the exact option-region geometry, and the pinned option-algorithm hash.
- Only reversible values `0xAA` and `0xBB` can be written. Irreversible RDP Level 2 (`0xCC`) is always rejected.
- Level 1-to-Level 0 uses the RM0451-mandated first option word `0x015500AA`; the operation permanently erases main Flash, data EEPROM, and backup registers.
- Security operations require power-cycle reset; unlock additionally requires connect-under-reset.
