# 手动 FLM 路径误报不可用

## 原因和修复

脱机烧录的手动 FLM 使用同一个 upload 来源类型，浏览器选择器返回 File，
桌面原生选择器返回 source_path。生成配置与后端部署原本都支持这两种形式，
但界面可用性判断只检查 File，导致桌面本地文件、下载器 U 盘文件被误判，
“生成预览”和“部署到 U 盘”被禁用。

修复将判断与构建请求一致：File 或 source_path 任一存在即允许继续。
没有修改 Pack、profile 或已存在算法的可用性判断；部署阶段仍检查真实
路径、扩展名、文件存在性和大小。U 盘源文件的暂存与同路径更新机制保留。

## 验证

- 旧代码的桌面、U 盘路径回归均出现同样的不可用提示；修复后两种路径和
  浏览器 File 上传三种回归都可生成预览，提交的来源字段正确。
- GUI 全量 64 个文件、678 项通过；脱机下载后端 60 项通过，含缺失算法
  拦截及 U 盘同路径文件暂存测试。测试期间纠正了预览按钮定位和模拟接口
  参数断言，未将这些中间失败计作通过。
- 源码 b32a0f8 的 TypeScript、生产 GUI 和标准 NSIS 构建成功。
- 实际桌面和 U 盘中的 STM32F10x_512.FLM 均可读取，两个文件内容相同；
  pyOCD 算法解析通过，Flash 起点 0x08000000、容量 512 KiB、页大小 1024 B。

- 真实 Edge 分别选择桌面和 U 盘中的实际 FLM，加上当前测试 HEX，生成预览
  HTTP 200；同一配置以桌面 source_path 形式请求预览也为 HTTP 200。
  零页面 JS 错误，三份源文件验证前后哈希一致。浏览器脚本首次过早检查了
  尚未完成初始化的按钮状态，改为等待算法行与实际预览响应后两种来源通过。
- Skill 运行时同步、配置保留，GUI 与桌面构建逐字节相同，无维护上下文；
  sidecar 和 Skill 均验证 7059 目标、2224 FLM 数据文件。
