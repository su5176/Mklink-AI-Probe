# v0.2.0 GD32F303CET6 加锁/解锁真机验证

## 验证对象

- 器件：`GD32F303CET6`，3.3 V。
- 只读身份：`DBG_ID=0x21040414`；工厂密度签名为 512 KiB Flash、64 KiB SRAM。
- 主 Flash：`0x08000000`–`0x08080000`，内置 `GD32F30x_HD.FLM`，SHA-256 `C8D2F112C594EDA8C85D07C605EB1C7F56DD0E765D4BCFFD9DBAC0497422A18C`。
- Option Byte：`0x1FFFF800`、16 字节，固定 `GD32F10x_OPT.FLM`，SHA-256 `4A2EFB1F314A4C70B4B9DE9561FD288D3F48C7A363570BAE5ACC2A2AEA72545A`。
- 官方依据：[GD32F30x User Manual Rev3.0](https://www.gd32mcu.com/data/documents/userManual/GD32F30x_User_Manual_Rev3.0.pdf) 与 [GD32F303xx Datasheet Rev3.0](https://www.gd32mcu.com/data/documents/datasheet/GD32F303xx_Datasheet_Rev3.0.pdf)。手册规定无保护 SPC 为 `A5/5A`，其他值进入保护；调试器连接期间修改 SPC 后必须断电复位；恢复 `A5/5A` 会整片擦除主 Flash。

## 真机闭环

1. 加锁前完整读取 512 KiB，首向量为 `F01D002049010008`，SHA-256 为 `65ED9D7373EEA85ED2CAE55D346260F651C83C326BF09CFAC6072357E5543699`。
2. CLI 在完整固件校验通过后写入 SPC `00/FF`，由下载器关闭 VCC 1 秒并以 3.3 V 恢复；`FMC_OBSTAT.SPC=1`，主 Flash 调试读取被拒绝。
3. MCP 共用入口以复位下连接写回 SPC `A5/5A`，再次执行 3.3 V 断电复位。保护状态清除后，逐块检查全部 524,288 字节均为 `FF`；擦除态 SHA-256 为 `043E238A765F7CFBC62596A50E53C8FFB6B188A99357B0EBEDE251725D67589F`。
4. 使用同一内置主 Flash 算法恢复完整镜像并校验，断电复位后再次完整回读；最终 SHA-256 与步骤 1 完全一致。
5. 原始非 SPC Option Byte 为擦除态 `FF/FF`；固定算法写入后规范化为等价补码态 `FF/00`，各逻辑选项值保持为 `FF`。

## 固化边界

- 启用 `GD32F303xE` 512 KiB 容量组，精确订货型号必须解析到匹配的内置目标。
- 每次写入前校验固定 Option FLM 名称、哈希、地址和长度，并核对 `DBG_ID`、SPC 物理值与影子状态。
- 未保护状态必须读取并匹配 512/64 KiB 工厂密度签名。保护状态下该签名区会返回 FAULT，此时只允许在 SPC 物理值与影子状态一致且家族 ID 匹配时执行解锁；若密度仍可读取则仍须精确匹配。
- 加锁只写可逆 SPC `00/FF`，解锁只写 `A5/5A`；两者均强制复位下连接规则和用户确认电压的 1 秒断电复位。
- 其他尚未完成同架构真机闭环的 GD32 系列继续置灰并由后端拒绝。
