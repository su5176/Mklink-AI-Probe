# v0.2.0 STM32F103RE 加锁/解锁真机验证

验证日期：2026-09-02

## 范围

- 目标：STM32F103 高密度器件，设备 ID `0x414`，512 KiB Flash。
- 固件：测试工程的 bootloader 与 app 两个 HEX，地址范围分别为 `0x08000000–0x08004A00` 和 `0x08005000–0x08020050`。
- 安全级别：仅验证可逆 RDP Level 1；未实现、未测试且禁止不可逆 Level 2。
- 算法：内置 `STM32F10x_OPT.FLM`，SHA-256 `4A2EFB1F314A4C70B4B9DE9561FD288D3F48C7A363570BAE5ACC2A2AEA72545A`，选项字节范围 `0x1FFFF800`、长度与页大小均为 16 字节。

## 结果

1. 加锁前分别校验 bootloader 与 app，二者均与板上 Flash 一致。
2. 写入 RDP Level 1 后由后端原子执行复位，重新连接时 `FLASH_OBR.RDPRT=1`；选项字节区及主 Flash 读取均稳定返回 `TARGET_LOCKED`。
3. 受保护状态下不直接读取选项字节，而是从 `FLASH_OBR` 与 `FLASH_WRPR` 影子寄存器重建 USER、DATA 和 WRP 配置，只修改 RDP 互补字节。
4. 解锁后完整回读 16 字节为 `A55AFF00FF00FF00FF00FF00FF00FF00`，确认原选项配置保持不变；主 Flash 前 256 字节全为 `FF`，确认硬件强制整片擦除。
5. 重新烧录并逐字节校验 bootloader 与 app，启动向量恢复为 `D01F002049010008F10F0008E90F0008ED0F00081D090008FD0F000800000000`，前 32 字节 SHA-256 恢复为 `EBC89E668E5801F424C6BA9B523041109AF8FC34C892F24266CCE046C744D99E`。
6. 加锁与解锁均通过硬件复位生效，本次验证未使用探针 VCC 断电重启。

## 安全结论

- 界面默认不勾选“解锁”和“加锁”；两项操作分别弹出明确确认。
- 解锁警告会说明 bootloader、应用和全部 Flash 数据均被永久擦除。
- 加锁只能紧跟校验并由后端立即复位确认生效。
- 型号、算法哈希、选项字节地址和长度均由后端白名单校验，客户端不能提供任意 FLM 或地址。
- GD32 及其他型号在完成各自真机闭环前保持置灰并由服务端拒绝。
