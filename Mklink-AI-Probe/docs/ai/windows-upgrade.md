# Windows 自动升级维护说明

## 0.1.7 → 0.1.8 问题

0.1.8 新增的 `installer-hooks.nsh` 在 `NSIS_HOOK_PREINSTALL` 中读取多个
卸载注册项并执行 `uninstall.exe /S`。这条路径没有区分普通安装和 Tauri
更新器传入的 `/UPDATE`，与 Tauri 的覆盖升级流程冲突。

NSIS 卸载器默认会复制到临时目录并启动另一个进程；只等待最初启动的进程
不能保证卸载完成。旧钩子未使用同步卸载所需的 `_?=`，因此可能在新版写入
期间继续删除程序文件。它也没有向卸载器传递 `/UPDATE`，会删除快捷方式；
Tauri 的更新模式则有意不重新创建快捷方式，尊重用户此前的删除选择。

因此，桌面图标消失并不能单独证明安装器完全没有写入新版；也可能是图标
被删除，或已写入的文件又被旧卸载进程删除。排查时必须核对安装文件、版本、
快捷方式目标和进程，而不能只看安装器退出码。

参考：[NSIS 卸载命令行规则](https://nsis.sourceforge.io/Docs/Chapter3.html#uninstallerusage)、
[Tauri 更新器](https://v2.tauri.app/plugin/updater/)。仓库使用的 Tauri NSIS
生成脚本中，`PageReinstallLeave` 在更新模式跳过卸载，快捷方式函数在更新
模式跳过新建；检查实际锁定版本生成的脚本，不依赖其他版本的行为。

## 0.1.9 修复策略

- 自定义钩子不再启动旧卸载器。普通安装和更新的重装决策交给 Tauri。
- 自动升级不由自定义钩子删除旧文件、旧注册项、快捷方式或用户配置。
- 0.1.7 为用户级安装，0.1.8 为全局安装。自动升级成功写入后，若旧用户级
  注册路径与新目录不同，仅将指向旧程序的已有桌面/开始菜单快捷方式改到新
  程序。已删除的快捷方式不恢复，指向其他程序的同名快捷方式不修改。
- 跨范围迁移留下的旧目录/注册项不自动清理，另行确认后处理，避免提前删除
  旧版或用户数据。不同 Windows 账号提权的迁移需单独验收。
- USB 端口命名仍为安装后的尽力执行步骤；没有连接探针不能使安装失败。

## 验收与发布边界

回归需覆盖 0.1.7 和 0.1.8 到候选版的同目录升级、用户级目录迁移、缺失或
被修改的快捷方式、用户配置保留，以及 `/P /UPDATE /R` 自动重启。
隔离 NSIS 流程测试的注册项、快捷方式、安装目录和可执行文件均是测试夹具，
可验证钩子行为，但不能替代正式安装包的完整升级验收。

发布前仍须使用实际签名候选包完成旧版更新检查、下载、签名验证、UAC、
安装、启动、后端健康和退出检查；不修改生产更新指针来运行测试。
已因旧版升级失败而没有可运行应用的用户，需要手动安装修复版本，无法再由
已经不存在的应用发起自动升级。
